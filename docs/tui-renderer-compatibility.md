# TUI 差量渲染兼容补丁

## 目的与边界

工作台的导航边框、表格行和路径输入会同时出现在同一终端画面中。渲染器按服务端操作系统启用硬滚动时，输出可能包含滚动区域、插入行和删除行；这些指令会搬动整块屏幕，客户端终端的兼容性差异可能表现为边框缺段、旧表格行残留。逐次清屏重画又会在部分终端产生闪烁，不能作为常规解决方式。

主界面和嵌套全屏编辑器统一使用 `shell.NewFullscreenProgram`，启用 `tea.WithConservativeRenderer()`：保留单元格差量刷新，关闭硬滚动、硬 Tab 和退格定位优化。普通导航、搜索、编辑和异步结果更新不主动清屏；初始化、真实窗口缩放及子进程返回仍按框架生命周期恢复画面。真实光标、输入法、剪贴板、鼠标、Batch/Sequence 和退出调度仍由 Bubble Tea 管理。

终端重新聚焦可能伴随重复尺寸通知。渲染器仅在宽度或高度实际变化时清屏恢复画面；相同尺寸通知不触发清屏或整屏重绘，也不取消真实缩放、显式清屏已经登记的待重绘状态。尺寸消息仍正常传给应用模型。

此前的 `RU_TUI_RENDER=full/diff` 包装已移除，这些变量不再改变程序行为；无需额外环境变量即可启用兼容修复。

## 固定来源与补丁

`third_party/bubbletea` 来自官方 Go 模块 `charm.land/bubbletea/v2@v2.1.0`，保留原始 MIT 许可证、生产代码、上游测试和测试数据。主模块通过 `go.mod` 的本地 `replace` 使用该固定源码，源码构建必须保留完整的 `third_party/bubbletea` 目录；不会改写系统 Go 模块缓存。

## 输入提交边界

全屏入口统一使用 15ms 文本聚合窗口，在 Shell 执行动作前保留本批字符总数。非编辑态只接受恰好两字符的合法 `r/R` 组合，其他双字符和所有三字符以上提交直接丢弃；编辑和搜索接收完整文本。终端无法统一提供输入法提交边界，这个窗口按事件到达间隔判定；超过窗口仍作为独立按键处理。完整行为见 [TUI 按键规范](tui-keybindings.md)。

## 验证

- `make test-terminal-renderer`：运行固定框架的上游测试与补丁测试。
- `make test-tui`：先执行框架测试，再执行全部 TUI 回归。
- `terminal_replay_test.go` 将渲染器输出送入独立 VT 终端回放，逐格比较多轮列表位移、页面切换后的画面，检测旧行残留和边框损坏。
- `fullscreen_program_test.go` 经过实际 Bubble Tea 程序捕获连续输出，验证普通更新、连续失焦/聚焦及重复尺寸通知不额外发送清屏、滚动区域或插入/删除行指令，也不使用硬 Tab/退格定位；实际缩放后继续逐格比较画面。
- `simple_mapping_replay_test.go` 使用真实映射控制器和 Shell，覆盖 13 条长路径映射、重复容器、翻页、搜索、表单切换和往返缩放后的连续终端画面，并逐格比较背景、可见文字前景、字体属性和下划线。
- 固定底色使用 256 色扩展索引，默认不强制 RGB；实际程序回归覆盖客户端忽略 RGB 时的黑底、普通正文、帮助说明和选中行。依据与限制见 [终端一致性源码对照](tui-terminal-consistency.md)。
- 非 PTY 测试按框架熟模式的 ONLCR 约定回放换行，原始渲染器测试保留原始字节约定，避免把测试端换行差异误判为错行。

上述测试验证程序输出与标准终端语义一致，不能替代具体 SSH 客户端的人工验收。验收时应确认列表移动、翻页、搜索、表单编辑、进入/退出弹框和往返缩放后，旧行不残留且普通更新不整屏闪烁。
