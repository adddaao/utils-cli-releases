# 部署模块与简单部署

运行 `ru`，进入第 5 项「部署」，包含两种部署方式：

- **AIOps 部署**：原有单实例部署、批量部署、远程初始化、状态查看、状态巡检、服务器、项目、部署拓扑、配置检查，下移到第三级，名称保持不变。原 `ru aiops` 命令保持可用，详见 [AIOps 远程部署与巡检](aiops.md)。
- **简单部署**：把本机交付包发布到本机 Docker 容器的宿主机 bind 挂载目录，包含「发布制品」「映射配置」「注册部署别名」。

## 默认配置与编辑

首次进入简单部署功能时，会通过 `internal/store` 创建 `<data_dir>/deploy/simple-deploy.toml`。`data_dir` 取当前配置的 `common.data_dir`，不依赖运行命令时的工作目录。已存在的文件不会被默认值覆盖。

新配置默认为空，不携带特定项目的路径、容器或 ZIP 密码；已有配置保持原样。每条映射包含 `kind`（jar/web）、`name`（文件名或通配模式）、`target`（宿主机现役目录）、`container`（重启容器）。

映射页只显示一张主窗口表格，可搜索、定位、编辑、新增、复制、删除和从路径自动识别；鼠标只定位，确认编辑由帮助栏声明的动作触发。删除映射使用连续两下 `d`：第一次 `d` 只在右下信息展示区显示待删除映射与影响范围，待确认状态一直保留到下一次按键；第二次 `d` 才校验并写盘，其他按键或移动光标会取消；保存失败保留原列表并显示具体原因，筛选词和光标按删除后的列表恢复。字段类型候选使用公共下拉，不再用弹框重复整份清单。保存失败保留草稿和具体原因。

支持直接读取原脚本的 `deploy-archive.conf` 生成映射配置，字段格式为 `类型|制品名|宿主机目录|容器`。空行、注释、UTF-8 BOM 和 CRLF 换行均可识别。完全重复的行跳过，有效项存在冲突时整批不写入。复制先打开草稿，修改冲突字段并保存后才生效。全部键位由帮助栏显示，删除为 `dd`，复制为 `r d`，导入为 `r i`（与打开生成物文件的 `r o/r O` 区分），导出空样例为 `r e`。

### 配置导入检查与空样例导出

导入必须在实际 Docker 宿主机上进行。每行先检查四列字段和 jar/web 扩展名，再检查当前环境；以下行自动过滤，并保留原始行号、制品名和具体原因：

- 字段数量、类型、文件名、绝对路径或容器名格式不正确，例如把 `.jar` 声明为 `web`。
- 宿主机现役目录不存在、不可访问或不是目录。
- JAR 现役目录没有唯一匹配文件（支持 `*`），或匹配文件不具备 JAR/ZIP 文件头。
- Web 现役目录没有普通文件 `index.html`。
- 指定容器不存在、Docker 无法读取该容器、镜像信息为空，或目标目录不属于其 bind 挂载；路径先解析软链接，指向挂载外的链接也过滤。

本四列格式只指定容器名，没有预期镜像名称、标签或摘要，因而不会根据自定义镜像名推断 Java/Web 运行能力，也不能核对预期镜像版本。容器名不能使用镜像名代替；停止的容器可检查，但 Docker 必须可访问。导入检查的是配置和现役环境，交付包中的实际内容在发布检查时继续验证。

同一制品支持多组目标，**每行的目录和容器是一对一关系**。重复填写相同的类型、文件名或通配规则，每行填写不同的目录与容器即可；界面中可复制映射后修改这两个字段。导入逐行检查，某组无效只过滤该组，其余组保留。部署会把同一份制品分别发布到各行目录，并仅重启该行配对的容器；不会把目录和容器交叉组合。每组 JAR 目录必须分别已有唯一匹配的待替换文件，Web 目录必须分别已有 `index.html`。例如：

```conf
jar|service-*.jar|/srv/service-a|service-a
jar|service-*.jar|/srv/service-b|service-b
web|admin-*.zip|/srv/admin-a|admin-a
web|admin-*.zip|/srv/admin-b|admin-b
```

不能把多个路径或容器用逗号放进一列，也不能复用同一制品的目录或容器；这类配置会被格式检查或冲突检查拒绝。

TUI 使用公共加载弹框异步检查，允许取消；只测试会留在原表单显示结果，不落盘。继续后，确认页展示有效映射和全部过滤原因，确认保存才更新配置。全部过滤或全部重复时不写盘，保留原配置和输入。检查失败、取消及过期结果均不得提交。CLI 输出过滤原因表格与新增/重复/过滤数量，只在确有新增项时保存。

映射页的「导出空样例」与 `ru deploy mappings export-template` 会在**运行时当前目录**创建 `deploy-archive_yyyyMMddHHMM.conf`；重名从 `_02` 递增，独占创建防止覆盖已有文件。文件带中文字段说明、校验规则以及已注释的 JAR/Web 样例，不导出现有项目映射，也没有生效配置。填写后移除对应样例行的注释即可导入。TUI 导出后立即显示完成或失败，成功提示优先显示实际文件名，再显示保存目录，避免长路径把名字挤到省略区域。5 秒短提示结束或按键关闭后，映射页右下信息区仍保留最近一次导出的成功/失败、样例文件名和保存目录；失败显示具体原因，不沿用上次生成物冒充成功。短提示可见期间使用公共生成物动作打开文件/文件夹；无桌面会话按公共环境规则隐藏打开动作。

新增、编辑、复制和集中补齐配置时，「容器」字段使用公共下拉选择。每次打开都会通过 Docker API 重新读取当前运行中的容器，每项只在一行显示容器名和「运行中」状态；下拉打开即显示并聚焦搜索框，可直接输入或粘贴进行模糊筛选，不再先按搜索快捷键。数字也作为查询文字，方向键定位候选，一次确认即可回填。列表按全部候选的最长内容确定宽度，最大 96 个终端显示单元（含边框），窗口较窄时继续收缩；超长名称在行内截断并保留状态，提交值仍是完整容器名。打开时定位已有容器名或 ID，确认后只回填当前字段，取消保留原值；最终保存时写入容器名。停止或暂停的容器不进入候选。Docker 连接失败或没有运行中容器时，保留全部草稿并在表单显示原因，可在 Docker 恢复或启动目标容器后重新选择。CLI 的集中编辑器复用同一选择流程。

校验规则：

- JAR 和压缩包都支持文件名 `*` 通配符（任意数量字符），例如 `service-*.jar`、`web-*-prod.tar.gz`；这是通配匹配，不是任意正则表达式。
- 同一制品可以发布到不同目录、不同容器；同一制品的目标目录或容器重复会拒绝保存。
- 不同匹配规则重叠、发布目标相同或相互包含时拒绝保存；部署前还会解析真实路径，避免路径别名绕过冲突检查。
- 目标必须是非根目录的绝对路径，类型、扩展名、容器名和字段分隔符都有校验。

## 从路径自动识别映射

在「简单部署 → 映射配置」页使用底部帮助栏中的 `i 从路径识别`，输入目录、单个 JAR 或支持的压缩文件路径；密码可留空，确认「识别制品」后统一检测。目录递归识别 JAR 和 Web 制品，交付压缩包识别其中的制品，单个前端压缩包按 Web 识别。路径输入复用公共补全与建议，密码只在本次使用。

检测结果自动过滤已有精确或通配映射。存在新制品时，在同一页集中填写目标目录与容器并一次保存，完成后返回原映射列表；此入口只维护映射。全部已配置时返回列表并显示无需新增。识别失败保留路径和密码，保存失败保留全部映射草稿；取消批量编辑回到路径表单，取消路径表单返回映射列表，原列表筛选保持不变。

## 发布流程

支持单个 JAR、前端压缩包、包含多个制品的交付包，以及递归查找的交付目录。支持 ZIP、TAR、tar.gz/tgz、tar.bz2/tbz2、tar.xz/txz、tar.zst/tzst、7z、RAR；先识别文件头，其他格式经隔离工作目录归一化为内部 ZIP，原始包不变。前端解压结果必须在根目录包含 `index.html`，或仅有一个顶层目录且其中包含 `index.html`。

密码默认为空，ZIP/7z/RAR 可在参数页提供本次密码；密码错误或包损坏时停止，返回参数页修改重试。配置不保存密码。

提交参数后先统一检测完整交付源，汇总全部未配置 JAR 和 Web 制品，再直接进入集中配置编辑界面。每项展示识别到的类型和实际制品名，目标目录与容器留空，由用户集中补齐；可关闭某项的「加入配置」开关，明确跳过该项。全部制品共用一组校验与保存按钮，整批通过校验后一次写入，不再逐个询问或逐条保存。校验或保存失败保留全部草稿，取消则整批不写盘。完成后恢复原部署参数并进入确认，跳过项列在确认页；没有任何可发布映射时停在参数页，不执行。窄窗口和多制品场景由公共多区块表单维护字段窗口，保证当前字段和保存按钮可见。

默认开启「仅检查」。参数通过本地校验后进入只读确认页，确认执行才开始完整检查；预演仍可能生成解压工作目录，但不会替换现役文件或重启容器。正式发布需要关闭「仅检查」并再次确认。

发布前检查全部候选：找不到的映射跳过，同一映射出现多个候选立即失败；未由用户明确跳过的未配置 JAR 会阻断。检查 JAR 文件头、压缩包完整性、压缩包路径穿越、链接和特殊文件、前端布局、现役目录/文件、容器存在性及目标是否位于该容器的宿主机 bind 挂载内。

JAR 通配映射要求交付候选和现役目录中都只有一个匹配；更新保留现役文件名，以维持容器启动路径。JAR 与现役文件内容一致时跳过替换和重启；前端包的 SHA-256 与同级 `.<目录名>.deploy-sha256` 一致时跳过替换和重启；ZIP 摘要与原脚本兼容，其他格式使用归一化后的稳定摘要。

更新时先准备新制品，把现役文件或目录移入同级 `bak/`，切换新制品并重启对应容器。切换或重启失败会尝试恢复当前项旧版本；重启失败的新制品以 `_failed` 后缀保留。多个映射逐项执行，后续失败不会自动回滚已经完成的其他映射，恢复后容器能否重新启动仍以日志为准。

工作目录、备份与失败制品均保留，不自动删除。交付包每次完整解压到独立目录，避免复用被改动的旧工作目录；执行视图显示格式识别、发布计划、备份路径与恢复结果。执行期间不会通过返回键重置任务；切换导航或其他模块时任务继续运行，日志与完成通知回送所属部署模块。完成后可查看日志并返回参数页修改重试。写操作与失败均进入统一日志/审计，密码不进入配置、确认页或日志。

## 运行条件与验证边界

发布、解包、SHA-256、文件复制和备份切换全部由 Go 实现，依赖随 ru 二进制打包。需在实际 Docker 宿主机运行并具备 Docker CLI 与对应文件权限；Linux 为主要验证环境。不要求安装 Bash 4、`unzip`、`xz`、`7z`、`unrar` 或 `sha256sum`，也不需要服务器上单独配置 Go 或 C 运行库。注册别名仍使用现有 Bash/Zsh 别名服务，与解包运行条件无关。

| 格式 | 内置实现 | 密码支持 |
| --- | --- | --- |
| ZIP | Go 标准库及 `github.com/yeka/zip` | ZipCrypto、AES-128/192/256 |
| TAR、Gzip、Bzip2 | Go 标准库 | 格式本身不提供密码加密 |
| XZ | `github.com/ulikunitz/xz` | 格式本身不提供密码加密 |
| Zstd | `github.com/klauspost/compress/zstd` | 格式本身不提供密码加密 |
| 7z | `github.com/bodgit/sevenzip` | 文件与文件头加密 |
| RAR | `github.com/nwaples/rardecode/v2` | RAR 3/5 文件与文件头加密 |

Gzip/Bzip2/XZ/Zstd 在这里指相应压缩的 TAR 交付包。仅识别文件头并不表示所有变体都受支持：遇到库无法解码的算法、损坏的内容或不安全条目时停止，不调用外部程序兜底。7z 额外验证条目 CRC，RAR 解码字典上限为 256 MiB。

`make test-simple-deploy` 包含配置冲突、TUI 编辑/复制与尺寸变化回归，并以隔离目录和 Docker 命令替身验证预演、备份替换、重复跳过、重启失败恢复、候选冲突、路径与链接拒绝、ZipCrypto/AES、加密 7z、RAR 3/5 及常见 TAR 压缩格式。部署测试把 PATH 限定为只有 Docker 替身，防止系统解压工具掩盖问题。

`make test-simple-deploy-linux` 将测试编译成无 CGO 的 Linux 可执行文件，在隔离、断网的 `alpine:3.20` 容器中执行，不挂载 Docker socket。默认测试架构跟随开发机，可用 `SIMPLE_DEPLOY_TEST_ARCH` 和 `SIMPLE_DEPLOY_TEST_IMAGE` 指定匹配的 Linux 架构及镜像。此验证不代表真实服务器、Docker 挂载或业务服务启动已经验收。

测试数据位于 `internal/simpledeploy/testdata/`：前端 7z、RAR（存储模式）和 Bzip2 包为本项目生成，内容仅为 `index.html`；测试期间不调用压缩软件。RAR 3/5 加密样本取自 [rarfile 测试目录](https://github.com/markokr/rarfile/tree/d2f7df6fc843dae356fd6b0a85971dc36fd6e757/test/files)，固定版本 `d2f7df6fc843dae356fd6b0a85971dc36fd6e757`，保留其 `RARFILE-LICENSE`。其中 `rar3-comment-psw.rar` 只加密注释，用于普通文件解码；其余加密样本验证正确密码展开、错误密码拒绝。

## CLI 与一键别名

CLI 和 TUI 使用同一份配置、识别与发布服务：

```bash
ru deploy scan ./delivery.tar.gz
ru deploy mappings
ru deploy mappings import ./deploy-archive.conf
ru deploy mappings export-template
ru deploy mappings add --type jar --name 'service-*.jar' --target /srv/service --container service
ru deploy mappings edit 1 --target /srv/new-service
ru deploy mappings copy 1 --target /srv/another-service --container another-service
ru deploy ./delivery.tar.gz --dry-run
ru deploy ./delivery.tar.gz --yes
```

终端中先完成统一检测，发现未配置制品时直接进入与 TUI 共用的集中编辑界面，集中填写路径、容器并一次保存，再返回 CLI 继续部署确认。需要填写目标目录和容器这两个参数时即使用界面编辑，单个制品也不再串行提问；多个制品集中在同一界面处理。非交互环境不自动新增映射；使用映射子命令预配置，或显式 `--skip-unmapped` 跳过。`--yes` 只确认正式发布，不授权自动添加配置；正式非交互部署必须提供该参数，预演不需要。`--interactive` 可显式启用集中编辑界面与发布确认；取消界面或确认输入结束即停止未确认动作。显式 `--skip-unmapped` 在终端中同样直接跳过，并汇总显示跳过项。密码默认从 `RU_DEPLOY_PASSWORD` 环境变量读取，也可通过 `--password-env` 指定其他变量名。

TUI 的「注册部署别名」和 `ru deploy register-alias` 共用已有的全局别名服务：自动识别当前用户与 Bash/Zsh 配置，默认注册 `da` 指向当前 ru 的 `deploy` 子命令；保留原配置、拒绝同名不同命令、重复注册不再追加。子进程不能替父 Shell 加载别名，当前终端可执行输出中的 `source` 命令，或一次注册并加载：

```bash
eval "$(ru deploy register-alias --shell-code)"
da ./delivery.tar.gz --dry-run
```
