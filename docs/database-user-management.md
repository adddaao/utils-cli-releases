# PostgreSQL 用户与数据库权限管理

> 正式技术文档入口见 [docs/README.md](README.md)。本文描述数据库管理模块中“用户与数据库”子流程的能力边界、参数语义、生成的 SQL、安全约束和验证范围。

## 功能定位

“用户与数据库”用于在已有 PostgreSQL 实例（本地 psql 或 Docker 容器）上完成一次可审计的账号与权限初始化：

- 创建或更新登录用户，并按需授予 `CREATEDB`、`CREATEROLE`、`SUPERUSER` 角色能力；
- 新建数据库、指定所有者，并把该数据库按权限级别授权给目标用户；
- 把一个已有数据库绑定给目标用户，并按需转移所有者。

正常执行计划不提供删除用户、删除数据库或回收权限入口；准备阶段失败时会对本次新建的对象执行补偿删除。

## 入口与流程

```
数据库管理 → PostgreSQL → 用户与数据库
  ├─ [1] 创建用户          → 配置页(操作=创建或更新用户)
  ├─ [2] 新建数据库并授权  → 配置页(操作=新建数据库并授权)
  └─ [3] 绑定已有数据库    → 配置页(操作=绑定已有数据库)
```

面包屑固定为“选择类型 → 用户与数据库 → 操作名 → 配置参数 → 执行 → 完成”，执行完成后返回同一操作的配置页，不会跳到导入/导出或备份流程。

## 参数说明

### 管理连接

| 字段 | 语义 |
| --- | --- |
| Docker 容器 | 选中后通过 `docker exec` 在容器内执行 `psql`；选择“不使用容器”时使用随程序或 `PATH` 中的 `psql` |
| 主机/IP/域名、端口 | 直连模式必填；容器模式下隐藏，仅在容器内 `psql` 不可用时作为随程序 `psql` 的后备地址 |
| 管理员用户、管理员密码 | 执行 `CREATE ROLE`、`CREATE DATABASE`、`GRANT`、`ALTER DATABASE` 的连接身份；密码为空时按需读取已保存密码，不写入表单 |
| 维护数据库 | 预检、创建用户或数据库、同步角色能力时连接的数据库，默认 `postgres`；授权事务连接目标数据库 |

### 用户与数据库

| 字段 | 语义 |
| --- | --- |
| 操作 | 创建或更新用户 / 新建数据库并授权 / 绑定已有数据库 |
| 创建或更新用户 | 关闭后只为已存在用户授权，语句计划中不再包含 `CREATE ROLE` / `ALTER ROLE` |
| 目标用户 | 可从服务器 `pg_roles` 列表选择，也可手动输入；作为角色名和授权对象 |
| 用户密码 | 留空表示不修改已有用户密码，也不会生成 `PASSWORD` 子句 |
| 允许创建数据库 / 允许创建角色 / 超级用户 | 仅“创建或更新用户”和“新建数据库并授权”显示；更新已有角色时，关闭选项会生成 `NOCREATEDB`、`NOCREATEROLE`、`NOSUPERUSER`；绑定数据库时不修改隐藏的角色能力 |
| 对象已存在时保留 | 执行前预检发现用户或数据库已存在时沿用现有对象并继续同步密码、所有者与权限；关闭则冲突在改动前直接失败 |
| 新建数据库名 | 仅“新建数据库并授权”显示 |
| 绑定数据库 | 仅“绑定已有数据库”显示；一次选择或手动输入一个已有数据库。多库输入会在连接前被拒绝 |
| 设为数据库所有者 | 生成 `ALTER DATABASE ... OWNER TO`；新建数据库后也在目标数据库事务单元内执行 |
| 权限级别 | 只读连接 / 读写 / 完全控制，见下节 |
| 模式 (Schema) | 表、序列、函数授权所在的模式，默认 `public`；“新建数据库并授权”时固定为 `public` 且只读展示 |

模式字段的两种行为：

- **新建数据库并授权**：此刻数据库尚不存在，新建库只可能有 `public` 模式，因此该字段固定显示为 `public` 且不可编辑，也不会去连接目标库读取模式列表（否则必然报 `database ... does not exist`）。如需授权其它模式，请先创建该模式，再用“绑定已有数据库”授权。
- **绑定已有数据库**：从已选数据库读取模式列表；未选择数据库时回退到维护库，只用于给出候选，不会修改目标库。

操作选择“创建或更新用户”时必须保持“创建或更新用户”开关开启，否则流程没有可执行语句，会在执行前提示；只做授权时选择“绑定已有数据库”，或关闭该开关并改做数据库操作。

## 权限级别与生成的 SQL

语句按“创建用户 → 同步用户属性 → 数据库 → 授权”顺序执行。预检、创建用户或数据库、同步角色能力使用维护库；数据库级、模式级及对象级授权连接目标数据库执行。

### 创建或更新用户

```sql
CREATE ROLE "app_user" WITH LOGIN [PASSWORD '...'] [CREATEDB] [CREATEROLE] [SUPERUSER];
ALTER ROLE "app_user" WITH LOGIN [PASSWORD '...'] [CREATEDB|NOCREATEDB] [CREATEROLE|NOCREATEROLE] [SUPERUSER|NOSUPERUSER];
```

- 预检发现用户不存在时生成 `CREATE ROLE`（含密码与角色能力）；用户已存在且开启“对象已存在时保留”时只生成 `ALTER ROLE` 同步密码与能力。
- 用户已存在但未开启该开关时，执行前直接失败，不会产生任何变更。
- 已存在用户且开启“创建或更新用户”时，先读取当前角色能力，再仅为发生变化的开关生成对应的授予或撤销子句；没有密码和能力变更时不生成角色语句。

### 新建数据库并授权

```sql
CREATE DATABASE "app_db";
-- 勾选“设为数据库所有者”时，在目标数据库事务单元内执行：
ALTER DATABASE "app_db" OWNER TO "app_user";
```

`CREATE DATABASE` 在维护库执行；随后的模式级、表、序列和函数授权会在**新建出来的 `app_db` 内**执行，模式固定为 `public`。

### 绑定已有数据库

```sql
ALTER DATABASE "app_db" OWNER TO "app_user";   -- 勾选“设为数据库所有者”时
```

### 权限级别

| 级别 | 生成的授权语句 |
| --- | --- |
| 只读连接 | `GRANT CONNECT ON DATABASE ...` |
| 读写 | `GRANT CONNECT, TEMPORARY ON DATABASE ...`；`GRANT USAGE ON SCHEMA ...`；现有表 `SELECT, INSERT, UPDATE, DELETE`；现有序列 `USAGE, SELECT`；并同步后续新表、新序列的默认权限 |
| 完全控制 | `GRANT ALL PRIVILEGES ON DATABASE ...`；`GRANT ALL ON SCHEMA ...`；现有表、序列、函数全部权限；并同步后续新表、新序列、新函数的默认权限 |

`ALTER DEFAULT PRIVILEGES` 的作用对象是执行该语句的管理员角色，即当前管理连接创建的新对象；其他角色创建的对象不会自动继承。

## 执行、日志与错误处理

- 进入执行页后按公共执行视图展示执行信息表格（任务、操作、目标用户、目标数据库、权限级别、执行方式、执行语句、已耗时）和日志区域。
- 每个先行步骤和事务单元上报 `阶段 i/n` 进度，日志记录脱敏后的语句原文，例如 `CREATE ROLE "app_user" WITH LOGIN PASSWORD '******'`。
- 任一非容忍错误会立即中止计划，错误信息带失败步骤名（例如 `授予连接权限: app_db 失败`），执行信息表状态转为“执行失败”。
- 语句包含的密码只用于真实执行参数，展示和日志中一律替换为 `'******'`。
- 执行成功后复用已有的连接历史机制保存主机、端口和管理员用户名；密码仍只通过既有加密存储保存，不写入 `config.toml` 明文。

## 执行失败与回退边界

绑定已有数据库一次只允许一个目标。执行前验证该限制，避免多个数据库逐个提交后留下部分生效的授权。已有角色的密码或能力修改与该数据库的授权放在同一个事务单元内；准备阶段任一语句失败，整个单元回滚。

### 回退机制

1. **先行创建**：新用户和新数据库必须提前单独创建；PostgreSQL 不允许在事务块内创建数据库。程序记录本次新建的对象，供准备失败时补偿。
2. **准备事务**：在唯一目标数据库执行 `BEGIN`、角色修改、所有者变更和授权；纯用户操作连接维护库。语句全部成功后保持事务打开，等待提交。
3. **准备失败时回退**：关闭未提交事务，并尝试通过 `DROP DATABASE IF EXISTS`（必要时 `WITH (FORCE)`）及 `DROP ROLE IF EXISTS` 补偿删除本次新建的对象。执行前已存在的对象不会被删除。
4. **提交**：只提交一个事务单元。若客户端在提交时失去确认，服务器可能已经提交，程序会明确报告“提交结果无法确认”，保留本次新建对象，避免误删已生效数据。这种情况下不能声称已回退。

| 失败场景 | 结果 |
| --- | --- |
| 多数据库绑定输入 | 在连接服务器前拒绝，不执行任何变更 |
| 事务内语句失败（权限不足、模式不存在等） | 整个单元回滚；随后尝试补偿本次先行新建的对象，并逐项报告结果 |
| `CREATE DATABASE` 失败 | 数据库未创建；此前若已新建用户，则尝试补偿删除该用户 |
| 目标对象已存在且未开启“对象已存在时保留” | 在产生变更前失败 |
| 目标用户不存在且未开启“创建或更新用户” | 在产生变更前失败 |
| 提交响应失败 | 唯一事务的提交结果可能不确定；执行页标记“回退未完成”，列出需要核查的事务和对象，不误报成功回退 |
| 补偿动作失败 | 执行页标记“回退未完成”，日志列出失败动作与原因 |

### 其他边界

| 能力 | 行为 |
| --- | --- |
| 对象已存在时保留 | 由执行前预检决定；已存在用户只同步所选属性，已存在数据库沿用并继续授权 |
| 容器通道回退 | 容器内执行失败时，整个事务单元改用随程序或 `PATH` 中的 `psql` 重试一次 |
| 绑定数据库粒度 | 一次只允许一个数据库；需要管理其它数据库时分别执行 |
| 参数保留 | 失败后 `Esc/q` 返回配置页，已填写参数保留，便于修正后重试 |
| 应用被强杀 | 未提交事务随连接断开回滚；先行创建的用户或数据库可能残留，需要核查 |
| 提交确认丢失 | 无法仅凭客户端错误判断事务是否已提交；程序保留现场并明确标记状态不确定 |

```bash

RU_INTEGRATION_POSTGRES=1 RU_INTEGRATION_POSTGRES_HOST=127.0.0.1 \

```

覆盖新建库流程中途失败后的对象补偿、绑定已有库失败后的授权回滚、多库请求在连接前被拒绝，以及成功路径下用户、所有者和授权的生效。

## 安全约束

1. 所有用户、数据库和模式标识符统一由 `quotePostgresIdentifier` 加双引号并转义内部双引号，避免标识符注入。
2. `ValidatePostgresIdentifier` 拒绝空值、超过 63 字节和控制字符；目标用户、新建数据库名、模式在执行前校验。
3. `BuildPostgresUserDatabasePlan` 生成不依赖服务器状态的预览草案；执行前再由 `ResolvePostgresUserDatabaseExecution` 根据对象状态确定实际语句，因此草案条数可能与实际不同。
4. 正常业务计划只生成创建、更新、授权和所有者变更语句；准备阶段失败时的补偿会对本次新建对象生成 `DROP`。
5. `SUPERUSER` 字段说明中明确提示风险；是否授予由用户显式勾选。
