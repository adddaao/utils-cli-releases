我将针对 `ConditionEditor` 进行全面的功能升级和体验优化，具体方案如下：

**功能优化清单**：

1.  **修复 UI 布局问题**：
    *   修复表格渲染错乱的问题（Terminal#1-11），确保空行或多行文本正确对齐。
    *   在底部增加独立的“命令预览”区域（Terminal#1-17），实时显示生成的 `find` 命令。

2.  **改进快捷键交互**：
    *   **删除功能**：将删除快捷键从 `Ctrl+C` 改为 `Delete` 键（`KeyDelete` 或 `Backspace` 在空闲时），符合用户直觉。
    *   **多选支持**：恢复 `Space` 键的多选功能，允许选中多行进行批量操作。
    *   **添加新行**：改为 `Ctrl+N` 添加新条件。

3.  **字段选择体验优化**：
    *   **Tab 键行为变更**：按下 `Tab` 键不再是简单的切换焦点，而是弹出字段选择列表（当焦点在字段列时）。
    *   **选择后自动添加**：选择字段后自动填充并添加该条件。

4.  **分组逻辑增强**：
    *   **新增“分组”列**：在表格中增加一列，用于显示分组信息（如 `(`, `)`）。
    *   **智能分组操作**：
        *   使用 `Space` 多选条件后，双击 `Space`（或特定快捷键）将选中的条件合并为一个组。
        *   自动在分组前后添加逻辑连接符（AND/OR）。

**文件修改**：
*   `internal/tui/finder_condition.go`:
    *   修改 `ConditionEditor` 结构体，增加多选状态支持。
    *   更新 `handleKey` 逻辑，映射新的快捷键。
    *   重构 `renderRow` 和 `renderTable`，修复显示异常并添加分组列。
    *   实现 `Tab` 弹窗选择逻辑（可能需要引入额外的 `list.Model`）。
*   `internal/finder/builder.go` (可能涉及):
    *   确保 `ConditionBuilder` 支持嵌套分组的构建逻辑。
