# 分组逻辑修复与重置功能增强计划

针对您反馈的两个问题，我制定了以下修复计划：

## 1. 修复分组拆分后的残留问题 (Terminal#5-9)

*   **问题分析**：
    *   当拆分 3 个元素的组（如 `A, B, C`）中间的 `B` 时，当前逻辑会将 `A` 和 `C` 分别设为独立的"单行组"（即同时拥有 Start 和 End 标记）。
    *   当再次取消这些"单行组"时，现有的代码逻辑（仅处理了 `len==2` 和 `else`）会错误地处理 `len=1` 的情况，导致标记错位（如只移除了 Start 没移除 End，或错误地将 Start 移到了下一行），从而出现 `)` 残留或 `(` 错位。

*   **修复方案** (`internal/tui/finder_condition.go`):
    *   **优化 `ungroupSelection`**：
        *   **处理单行组**：明确增加 `groupLen <= 2` 的判断。如果组内元素少于等于 2 个，直接**彻底移除**该组的所有 Start/End 标记，不留后患。
        *   **防止生成单行组**：在拆分中间元素时（`else` 分支），检查拆分后的左右两部分。如果某一部分只剩 1 个元素，则**不**为该部分创建新的分组标记。只有当剩余部分 >= 2 个元素时，才保留分组。
        *   这能保证分组永远至少包含 2 个元素，避免了"单行组"带来的逻辑陷阱。

## 2. 修复 Ctrl+L 重置分组无效

*   **问题分析**：
    *   当前的 `CleanInvalid` 仅检查了括号数量是否平衡，无法检测括号顺序错乱（如 `) (`）或嵌套错误。且用户对"重置"的期望通常是"清空所有分组"。

*   **修复方案** (`internal/find/builder.go`):
    *   **重写 `CleanInvalid`**：将其逻辑改为**强制清空所有分组信息** (`groupStarts` 和 `groupEnds` 重置为空 map)。
    *   这将作为一个"紧急复位"按钮，当界面显示混乱时，按下 `Ctrl+L` 即可瞬间清除所有括号，只保留条件内容，恢复界面的整洁。

## 执行步骤

1.  修改 `internal/tui/finder_condition.go`: 升级取消分组逻辑，防止产生和错误处理单行组。
2.  修改 `internal/find/builder.go`: 将 `CleanInvalid` 改为彻底重置分组。
