## 结论
- 程序未读取 `/Users/renx/projects/r/utils-cli/.Rutils/config.toml` 的两个主要原因：
  - 路径选择：未带 `--debug` 时加载 `~/.Rutils/config.toml`，不读取项目根的 `./.Rutils/config.toml`（internal/config/config.go:77-89）。
  - 键名不匹配：代码期望 `[maven]` 下为 `target.suffixes` 与 `default.paths`，当前文件为 `suffixes` 与 `paths`，导致值未映射到 `cfg.Maven`（internal/config/config.go:58-64 结构定义处）。

## 修复方案
- 路径行为
  - 在 `Load` 中保留现有逻辑，但增加调试日志已存在，便于确认使用路径（internal/config/config.go:105-110）。
  - 明确运行方式：本地项目配置需通过 `--debug` 加载；否则使用 `~/.Rutils/config.toml`。
- 键名兼容
  - 修改 `AppConfig.Maven` 字段标签为 `mapstructure:"suffixes"` 和 `mapstructure:"paths"`，兼容当前配置。
  - 同步修改默认值设置：`v.SetDefault("maven.suffixes", [...])` 与 `v.SetDefault("maven.paths", [...])`。
  - 同步修改 `defaultToml()` 模板，输出 `[maven]` 下使用 `suffixes` 与 `paths`。
- 交互入口
  - main 菜单已接入 maven 模块（cmd/dit/main.go:64-83、102-171），无需额外变更。

## 验证
- `make build` 后：
  - 执行 `./build/bin/RUtil --debug maven clean`，确认读取 `./.Rutils/config.toml` 的 `[maven]` 配置。
  - 执行不带 `--debug`：确认读取 `~/.Rutils/config.toml`。
- 修改 `[maven]` 的 `suffixes/paths`，清理统计输出应随之变化。
