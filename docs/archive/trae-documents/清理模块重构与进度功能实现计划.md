此计划将重构 `internal/clean` 模块以支持清理前的检查、进度显示以及流程控制的改进。

### 1. 核心接口重构 (`internal/clean/interface.go`)
- **定义 `Entry` 结构体**：用于描述待删除的项（路径、大小等）。
- **修改 `Rule` 接口**：
  - 移除 `Execute` 方法。
  - 新增 `Scan(ctx, paths, onProgress) ([]Entry, error)`：用于扫描并返回待清理项。
  - 新增 `Delete(ctx, entries, onProgress) (Result, error)`：用于执行具体的删除操作。

### 2. 管理器逻辑更新 (`internal/clean/manager.go`)
- 实现 `ScanSelected`：并发调用各规则的 `Scan` 方法，收集扫描结果。
- 实现 `DeleteSelected`：并发调用各规则的 `Delete` 方法，执行清理。
- 确保进度回调能正确传递给 UI。

### 3. UI 与进度条工具 (`internal/ui/progress.go`)
- 新增简单的进度条工具，支持：
  - **Spinner/Counter**：用于扫描阶段（因为不知道总数）。
  - **ProgressBar**：用于删除阶段（已知总数，显示百分比和计数）。

### 4. 规则实现更新
将现有规则（Maven, MacOS, Archive, Temp, Generic）的 `Execute` 逻辑拆分为 `Scan` 和 `Delete`：
- **`Scan`**：负责遍历目录、匹配文件、计算大小（Stat），返回 `[]Entry`。
- **`Delete`**：接收 `[]Entry`，执行 `os.Remove`，并统计实际释放空间和错误。
- **涉及文件**：
  - `internal/clean/maven.go`
  - `internal/clean/macos.go`
  - `internal/clean/archive.go`
  - `internal/clean/temp.go`
  - `internal/clean/generic.go`

### 5. 命令行交互流程改造 (`internal/clean/cmd.go`)
改造 `RunE` 逻辑以支持新流程：
1. **规则选择**（现有）。
2. **操作菜单**：
   - `[1] 检查待清理项` -> 进入扫描流程 -> 显示报告 -> 再次询问（执行/返回）。
   - `[2] 直接执行清理` -> 内部顺序调用 扫描 -> 删除。
3. **进度显示**：在扫描和执行阶段调用 UI 工具显示实时进度。

### 6. 验证计划
- 运行 `dit clean`。
- 验证“检查”功能是否准确列出文件和大小。
- 验证“直接执行”是否正常工作。
- 验证进度条显示是否流畅。
- 验证“返回规则选择”是否有效。
