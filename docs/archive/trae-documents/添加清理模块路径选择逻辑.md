# 添加路径选择与覆盖逻辑

本计划旨在实现 `clean` 命令在选择规则后的路径选择逻辑，支持用户输入自定义路径覆盖规则默认配置。

## 1. 接口更新 (`internal/clean/interface.go`)
- 修改 `Rule` 接口的 `Execute` 方法签名：
  - 原：`Execute(ctx context.Context, dryRun bool) (Result, error)`
  - 新：`Execute(ctx context.Context, paths []string, dryRun bool) (Result, error)`
- 说明：`paths` 参数用于接收外部传入的覆盖路径。如果 `paths` 为空，规则应使用其默认配置路径。

## 2. 规则实现更新 (`internal/clean/*.go`)
- 更新 `MavenRule`, `MacOSRule`, `ArchiveRule`, `TempRule`, `GenericRule` 的 `Execute` 方法。
- 逻辑变更：优先使用传入的 `paths` 参数。若为空，则回退到读取配置文件的逻辑。
- 注意：`MavenRule` 的默认路径逻辑保持不变（从配置读取 `DefaultPaths`），但现在允许被覆盖。

## 3. 管理器更新 (`internal/clean/manager.go`)
- 更新 `ExecuteAll` 和 `ExecuteSelected` 方法，接受 `paths []string` 参数，并传递给具体的 `Rule.Execute`。

## 4. 交互逻辑更新 (`internal/clean/cmd.go`)
- 在规则选择（或通过 flag 指定）后，添加路径选择交互：
  1. **检查选中规则**：遍历 `selectedIDs`，判断是否包含 Maven 规则（ID 为 `maven`）。
  2. **确定提示语**：
     - 若包含 Maven：`"请输入扫描路径 (留空使用默认配置)"`
     - 若不含 Maven：`"请输入扫描路径 (留空默认当前目录 .)"`
  3. **获取输入**：调用 `ui.PromptText`（允许为空）。
  4. **处理路径逻辑**：
     - 若用户输入了路径：`targetPaths = [input]`。
     - 若用户未输入（空）：
       - 若包含 Maven：`targetPaths = nil` (触发规则内部默认配置)。
       - 若不含 Maven：`targetPaths = ["."]` (强制当前目录)。
  5. **执行前提示**：
     - 打印将要执行的路径信息（如 "扫描路径: [用户输入]" 或 "使用各规则默认路径"）。
  6. **调用执行**：将 `targetPaths` 传递给 `manager.ExecuteSelected`。

## 5. 验证
- 验证含 Maven 规则且留空时，是否使用 Maven 默认路径。
- 验证不含 Maven 规则且留空时，是否使用当前目录。
- 验证输入路径时，是否所有规则都扫描该路径。
