# 清理模块重构与进度功能实现计划 (修正版)

根据您的反馈，我优化了计划，将重点改进进度条的视觉效果并完善交互流程。

## 1. 扩展管理器 (`internal/clean/manager.go`)

* **`ScanSelected`**: 仅执行扫描阶段，返回待清理的文件列表 (`[]Entry`)。

* **`DeleteSelected`**: 接收扫描结果，执行删除阶段。

* **`DefaultPaths`**: 确保所有规则都实现了此方法（修复之前的编译错误遗留）。

## 2. 打造现代化进度条 (`internal/ui/progress.go`)

升级 `ProgressTracker`，使其更具现代感：

* **视觉升级**：使用 `lipgloss` 库进行渲染，支持彩色输出。

* **样式改进**：

  * **扫描阶段**：使用动态 Spinner 效果（如 `⠋ ⠙ ⠹ ...`）配合彩色计数器，代替简单的文本。

  * **删除阶段**：使用块状字符（`████░░░`）渲染平滑的进度条，并显示具体的百分比和数量进度。

* **API 保持兼容**：继续使用 `Update(msg, inc)` 接口。

## 3. 改造命令行交互 (`internal/clean/cmd.go`)

重构 `RunE` 逻辑，将其封装在主循环中以支持“返回”操作：

1. **主循环开始**：
2. **规则与路径选择**（用户交互）。
3. **操作选择菜单**：

   * `[1]  扫描并检查`：进入扫描流程，展示现代化 Spinner。

   * `[2]  直接清理`：跳过检查，直接进入删除流程。
4. **扫描结果页**（若选择扫描）：

   * 展示详细报告（按规则分类的文件数、大小）。

   * **后续操作选择**：

     * `[1] 确认清理`：执行删除。

     * `[2] 返回规则选择`：清空状态，回到步骤 2。

     * `[0] 取消退出`：结束程序。
5. **清理执行**：

   * 展示现代化进度条。

   * 完成后显示最终报告。

此计划将实现一个视觉美观且流程灵活的清理工具。
