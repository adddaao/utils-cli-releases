# 文件扫描模块升级计划

基于 `internal/tui/文件扫描优化.md` 提供的并发扫描方案，对现有的清理模块进行重构，以提升性能和用户体验。

## 1. 新增核心扫描组件 (`internal/clean/scanner.go`)

创建一个通用的 `FileScanner` 结构体和相关方法，实现以下核心功能：

* **并发扫描**: 使用 `sync.WaitGroup` 和 buffered channel 实现并发目录遍历。

* **并发控制**: 引入信号量机制（Semaphore）限制最大并发数（如 `runtime.NumCPU() * 2`），避免文件句柄耗尽。

* **上下文支持**: 深度集成 `context.Context`，确保扫描任务可被立即取消。

* **进度反馈**: 支持 `onProgress` 回调，与现有的 TUI 界面无缝对接。

* **过滤机制**: 新增常见无关目录的排除开关。内置对 `.git`, `node_modules` 等常见无关目录的排除，支持文件后缀和大小过滤。

## 2. 重构现有规则 (`Refactoring`)

将现有的 `filepath.WalkDir` 串行实现替换为新的 `FileScanner`。

### 2.1 Maven 清理规则 (`internal/clean/maven.go`)

* 配置 Scanner 仅扫描 `.lastUpdated`, `.sha1`, `.repositories` 等特定后缀。

* 复用 Scanner 的目录排除功能，跳过无关文件夹。

### 2.2 通用清理规则 (`internal/clean/generic.go`)

* 根据用户配置（`GenericRuleConfig`）动态初始化 Scanner。

* 传入用户定义的后缀列表和路径。

### 2.3 macOS 清理规则 (`internal/clean/macos.go`)

* 适配新的 Scanner 接口，扫描 `.DS_Store` 等文件。

## 3. 验证与测试

* 确保所有规则在并发模式下能正确收集到文件 `Entry`。

* 验证取消操作（Cancel）的响应速度。

* 确保 UI 进度条能正常更新。
