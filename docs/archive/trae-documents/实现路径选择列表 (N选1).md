# 重构路径选择与执行流程

根据用户详细的路径清理执行流程需求，我们将对 `internal/tui/clean.go` 进行重构。

## 1. 状态机扩展 (`internal/tui/clean.go`)
- 现有的 `cleanStateInputPath` (输入路径) 和 `cleanStateConfirm` (确认) 不足以支撑新的流程。
- 新增状态：
  - `cleanStateMavenConfirm`: 询问是否使用 Maven 默认路径。
  - `cleanStatePathSelect`: 从规则默认路径列表中选择。

## 2. 流程实现逻辑
### 2.1 路径输入 (`cleanStateInputPath`)
- 用户输入路径。
- 如果输入有效 -> `m.targetPaths = [path]` -> 跳转至 `cleanStateConfirm` (跳过后续路径选择)。
- 如果输入为空 -> 进入 Maven 检查流程。

### 2.2 Maven 优先处理 (`cleanStateMavenConfirm`)
- 检查已选规则中是否包含 `maven`。
  - **有 Maven**: 进入 `cleanStateMavenConfirm` 状态，询问 "是否使用 maven 默认路径？(y/n)"。
    - **是 (y)**: 获取 Maven 规则的默认路径 -> `m.targetPaths = mavenDefaults` -> 跳转至 `cleanStateConfirm`。
    - **否 (n)**: 进入默认路径整合选择流程 (`cleanStatePathSelect`)。
  - **无 Maven**: 直接进入默认路径整合选择流程 (`cleanStatePathSelect`)。

### 2.3 默认路径整合与选择 (`cleanStatePathSelect`)
- 收集所有已选规则的 `DefaultPaths()`。
- 去重处理：
  - 如果路径为 `.`，替换为 `os.Getwd()`。
- 界面展示：
  - 使用 `list.Model` 展示去重后的路径列表。
  - 允许用户单选（Enter 确认）。
- 选中后 -> `m.targetPaths = [selectedPath]` -> 跳转至 `cleanStateConfirm`。

### 2.4 最终确认与执行 (`cleanStateConfirm` -> `cleanStateExecuting`)
- 展示最终确定的 `m.targetPaths`。
- 执行时，将此路径传递给所有选中的规则（覆盖规则原有路径）。

## 3. UI 组件调整
- `CleanModel` 需要第二个 `list.Model` 用于路径选择（或者复用现有的 list，但需切换 delegate 和 items，建议复用以节省资源，需注意状态管理）。
- `textinput` 保持用于手动输入。

## 4. 实施步骤
1. **定义新状态**: 修改 `cleanState` 枚举。
2. **重构 `Update` 逻辑**:
   - 按照 1->2->3 的优先级流转状态。
   - 实现路径收集与去重逻辑。
3. **实现路径选择视图**:
   - 当状态为 `cleanStatePathSelect` 时，配置 `m.list` 显示路径选项。
4. **完善确认视图**:
   - 清晰展示最终路径来源。
