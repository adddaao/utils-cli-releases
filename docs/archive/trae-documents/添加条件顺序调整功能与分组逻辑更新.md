# 添加条件顺序调整功能

## 1. 修改 `internal/find/builder.go`

添加 `MoveCondition` 方法，用于交换条件行及其关联的分组标记。

* **功能**: 支持将指定索引的条件移动到新位置。

* **逻辑**:

  * 交换 `conditions` 切片中的元素。

  * 交换 `groupStarts` 和 `groupEnds` 映射中的对应标记，确保分组标记跟随**位置**而非元素（或者跟随元素？根据推演，标记跟随**元素**能实现"移出即排除"的效果）。

  * **更正**: 根据用户需求 "超出分组...自动排除当前要素"，实际上是要求**分组标记保留在原地（或者说保留在原来的边界元素上），而移动的元素脱离分组**。

  * 采取策略：**交换元素内容，同时交换该元素携带的分组标记**。

    * 例如 `A(Start) B C(End)`。移动 `B` 到 `C` 后面。

    * 交换 `B` 和 `C`。

    * `B` 无标记，`C` 有 `End` 标记。

    * 交换后：位置 1 变为 `C` (带 End)，位置 2 变为 `B` (无标记)。

    * 结果：`A(Start) C(End) B`。此时 `B` 在组外。符合需求。

  * 处理逻辑符 `Logic` 的规范化（确保最后一个条件无逻辑符，中间条件有逻辑符）。

## 2. 修改 `internal/tui/finder_condition.go`

更新 UI 以支持移动模式。

* **状态管理**:

  * 添加 `CondStateMoving` 状态。

* **按键绑定**:

  * 添加 `Ctrl + M `键（Move）：在 `Idle` 和 `Moving` 状态间切换。

  * 在 `Moving` 状态下：

    * `↑` / `k` / `Ctrl+Up`: 将当前行向上移动。

    * `↓` / `j` / `Ctrl+Down`: 将当前行向下移动。

* **视觉反馈**:

  * 在 `renderRow` 中，当处于 `Moving` 状态时，改变选中行的样式（如变为黄色或添加图标 `↕`），提示用户当前处于移动模式。

  * 移动时实时刷新列表。

## 3. 验证计划

* **移动出组**: 测试将组内元素移出组边界，验证其是否被排除。

* **移动入组**: 测试将组外元素移入组内，验证其是否被包含（逻辑上应该被包含）。

* **边界移动**: 测试移动分组的起始/结束行，验证分组范围是否随之调整。
