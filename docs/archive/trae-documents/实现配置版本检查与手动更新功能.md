# 配置版本检查与手动更新计划

## 1. 核心需求分析
- **版本检查**：程序启动时（或加载配置时），对比程序内置的配置版本与配置文件中的版本。若不一致，提示用户升级。
- **手动更新**：
    - 在主菜单添加 "update" 选项。
    - 触发更新逻辑：
        1. 备份现有配置文件（如 `config.toml.bak`）。
        2. 写入最新的默认配置文件（包含新字段）。
        3. 提示用户手动迁移自定义配置。

## 2. 代码变更详情

### 2.1 配置版本管理 (`internal/config/config.go`)
- **常量定义**：定义当前程序的配置版本号 `CurrentConfigVersion = 2` (此前为 1)。
- **版本检查逻辑 (`CheckVersion`)**：
    - 在 `Load` 函数末尾调用。
    - 比较 `AppConfig.Common.ConfigVersion` 与 `CurrentConfigVersion`。
    - 若小于当前版本，打印警告信息："配置文件版本过旧 (vX < vY)，建议运行 'update' 更新配置"。
- **更新逻辑 (`UpdateConfig`)**：
    - 备份：`os.Rename(cfgPath, cfgPath + ".bak")`。
    - 重写：`os.WriteFile(cfgPath, defaultToml(), 0600)`。
    - 返回：更新结果与备份路径。

### 2.2 CLI 交互更新 (`cmd/dit/main.go`)
- **主菜单更新**：
    - 新增选项：`3) update (更新配置)`。
    - 响应输入：`3`, `update`, `u`。
- **执行逻辑**：
    - 调用 `config.UpdateConfig()`。
    - 成功后提示："配置文件已更新，旧文件备份为 xxx，请手动迁移自定义配置。"
    - 失败提示错误信息。

### 2.3 配置文件内容更新 (`internal/config/config.go`)
- **defaultToml**：
    - 将 `config_version = 1` 更新为 `config_version = 2`。
    - 确保包含最新的 `[clean]` 模块配置。

## 3. 执行步骤
1.  **修改 `internal/config/config.go`**：
    - 增加 `CurrentConfigVersion` 常量。
    - 实现 `CheckVersion` 并在 `Load` 中调用。
    - 实现 `UpdateConfig` 函数。
    - 更新 `defaultToml` 中的版本号。
2.  **修改 `cmd/dit/main.go`**：
    - 更新 `runMainMenu` 添加 update 选项与处理逻辑。
3.  **验证**：
    - 运行程序，观察版本检查提示。
    - 执行 update，验证备份与新文件生成。
