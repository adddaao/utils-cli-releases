01 / 功能模块

一个入口，八种日常

每个模块先是一个完整的 TUI 流程，再提供可脚本化的 CLI 入口。不用记命令，也不会在任务做到一半时忘记自己走到哪一步。

模块文档
01

Docker 管理

镜像、容器、网络、磁盘、服务与离线安装。通过 Go SDK 直连 daemon，不依赖本机 docker CLI。

docker · 镜像批量导出 / 导入
02

文件清理

Maven、macOS 元数据、压缩包、临时文件与自定义规则清理；所有删除走废纸篓语义。

clean · 扫描后先确认再执行
03

Find 文件查找

TUI-only 的条件构建器、模板与历史记录；路径补全、近期候选与结果即时预览。

find · 条件组合 / 搜索结果
04

数据库管理

PostgreSQL 导入导出、全量备份、校验、Docker 恢复演练、保留策略、计划任务与用户权限。

database · 备份计划 / 权限
05

部署

AIOps 远程部署与简单部署：配置检查、单实例/批量部署、远程初始化、状态巡检与交付包映射。

deploy · SSH / 本地目标
06

防火墙

Linux UFW / firewalld / iptables 与 Windows Defender Firewall 的 TCP 入站规则管理，按环境显隐。

firewall · 仅展示可用平台

把 root 可访问的文件或目录交付给普通登录用户；支持 Shell 别名注册、移动语义与目标冲突保护。

export · 原生 Linux
08

工具与诊断

随机密码生成、ru doctor 结构化环境诊断、安装与语义化版本 tag 管理。

tools · password / doctor / install

02 / 双入口

TUI 与 CLI 共用一套服务

03 / 安全删除

危险操作有分寸

不可恢复的删除需要连续两次 d，第一次只登记目标并展示影响范围；所有文件删除最终进入废纸篓。

d待确认：目标与影响范围
d→执行·其他按键取消
04 / 本地边界

配置与凭证留在本机

配置与加密凭证存于当前用户的数据目录，密钥按模块隔离；Docker 通过 Go SDK 直连，不要求本机 docker CLI。

~/.local/share/ru
├─ config.toml
├─ credentials/模块/密钥
└─ logs/ 按等级轮转
05 / 平台门控

能力跟着环境走

防火墙、文件中转、Systemd 服务等能力按平台与权限显隐；禁用能力不会伪装成可用，开发入口只做预览。

LinuxmacOSWindowsWSLLinux + root
06 / 质量

测试分层，未验证不冒充通过

单元测试与质量守卫走 make test；真实 Docker、SSH 与防火墙环境通过显式开关启用。未设置开关的集成测试报告跳过，设置后缺参数或连接失败则直接失败。

✓ go test ./...   · 质量守卫
↷ RU_INTEGRATION_DOCKER=1 make test-integration   跳过真实环境
↷ RU_INTEGRATION_AIOPS=1   未启用时跳过

04 / 命令行

批处理时，命令行就够了

TUI 适合探索与确认，CLI 适合重复执行与放进脚本。下面是常用入口，完整参数以 ru <命令> --help 为准。

CLI 速查
zsh — ru 
# 查看镜像与磁盘占用
$ ru list
$ ru docker images-size

# 批量保存与加载（压缩 / 并发）
$ ru save --all --compress gzip --output ./images --concurrency 4
$ ru load --input ./images --recurse --concurrency 4

# 容器与资源概览
$ ru docker containers list
$ ru docker stats nginx
# 备份计划与执行
$ ru database backup list
$ ru database backup run --plan 生产库-每日全量

# 校验与隔离恢复演练
$ ru database backup verify --file /backup/pg_20261103.dump
$ ru database backup restore-test --file /backup/pg_20261103.dump

# 系统计划任务
$ ru database backup schedule install --plan 生产库-每日全量
$ ru database backup schedule status --plan 生产库-每日全量
# 服务器、配置与状态
$ ru aiops servers
$ ru aiops check-config
$ ru aiops status --server 生产服务器
$ ru aiops inspect --all

# 单实例 / 批量部署
$ ru aiops deploy --server 生产服务器 --project api --local-path ./target --select api.jar
$ ru aiops multi-deploy --server 生产服务器 --project api --local-path ./target --select api.jar
# 环境诊断：人读、机读、严格模式
$ ru doctor
$ ru doctor --json
$ ru doctor --strict
$ ru doctor --fix-plan

# 输出检查项、结论与只读修复建议
config       ok     ~/.local/share/ru/config.toml
docker       ok     daemon reachable
trash        warn   sidecar not found; PATH fallback
# 随机密码
$ ru tools password
$ ru tools password --format hex --bytes 16
$ ru tools password --format alnum --length 24

# 自安装与版本 tag
$ ru install
$ ru git tag

05 / 安装

一行安装，先跑一遍诊断

发布安装器自动识别系统与架构、校验 SHA-256 后执行包内安装；替换旧目标时按废纸篓语义处理。升级或离线环境也保留明确入口。

GitHub Releases
install — ru 
$ curl -fsSL https://github.com/adddaao/utils-cli-releases/releases/latest/download/install.sh | sh
PS> powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "[Net.ServicePointManager]::SecurityProtocol = [Net.ServicePointManager]::SecurityProtocol -bor 3072; irm 'https://github.com/adddaao/utils-cli-releases/releases/latest/download/install.ps1' | iex"

默认下载源为 adddaao/utils-cli-releases。自建 Gitea 或私有发布仓库时，安装前设置 RU_RELEASE_BASE_URL，必要时再用 RU_VERSION 固定版本。离线安装可把发布包与同名 .sha256 带至目标机后执行 sh ./install.sh /path/to/ru-*.tar.gz。
一键安装默认获取最新正式版（当前 v0.2.6）；若要与本页展示的预览线功能一致，请从 Releases 选择对应的 v0.3.2 preview 附件。

  1. 安装并确认版本
    运行 ru version 与 ru --help，确认命令入口已加入当前会话的 PATH。
  2. 运行环境诊断
    ru doctor 检查配置、权限、Docker、客户端与计划任务；需要机读结果时加 --json。
  3. 打开工作台
    直接运行 ru，用 ↑ ↓ 选择模块，Enter 进入，Ctrl+C 退出。
Docker 模块需要可访问的 daemon；PostgreSQL 客户端随发布包提供。配置文件与凭证存放在当前用户的数据目录，不写入仓库。

06 / 平台

能力跟着环境走

同一份代码在 Linux、macOS、Windows 与 WSL 上按能力显隐模块。不能用就是不能用，不会把不支持的入口伪装成可用。

平台支持文档
能力LinuxmacOSWindowsWSL

PostgreSQL 备份 / 恢复演练✓✓✓部分

AIOps 远程部署 / 巡检✓✓✓✓

“部分”表示功能存在平台边界：例如 WSL 不提供系统计划任务，数据库备份仍可手动执行；AIOps 本地目标仅支持 POSIX 用户态；Docker 相关能力需要 daemon 可访问，回收站删除依赖随包或 PATH 中的 trash。完整矩阵与门控方式见 docs/platform-support.md。
